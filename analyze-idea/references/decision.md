# G1/G2 检查表与决策矩阵（decision.md）

## G1 快速筛选（否决项）

任一命中 → No-Go 或大幅重定向，不进入深度分析。

| # | 否决问题 | 命中？ | 说明 |
|---|---|---|---|
| 1 | 违法、违规或踩行业监管红线？ | ☐ | 有疑问就标"需确认"，不放过 |
| 2 | 明显超出提出者资源边界（钱/人/时间/渠道）？ | ☐ | 不是"要努力"，是"现在没有且短期补不上" |
| 3 | 明显没有付费方？ | ☐ | 谁掏钱、为什么掏，说不出来就命中 |
| 4 | 明显红海且毫无差异化？ | ☐ | 有差异化但没证据 = 也算命中待证 |
| 5 | 与现有主营业务冲突、会伤主业？ | ☐ | 机会成本、资源挤占、口碑风险 |

结论：☐ 通过（进入 S2）　☐ 否决（No-Go/重定向，写明理由）

## G2 决策矩阵

六维度评分（1-5）+ 加权总分：

| 维度 | 权重 | 分数 | 依据摘要 |
|---|---|---|---|
| 客户与痛点 | 20% | /5 | |
| 市场与时机 | 15% | /5 | |
| 商业模式 | 20% | /5 | |
| 资源与竞争 | 15% | /5 | |
| 风险与合规 | 15% | /5 | |
| 验证路径 | 15% | /5 | |
| **加权总分** | 100% | **/5** | |

参考阈值（脚本输出一致）：
- ≥ 3.5：倾向 Go
- 2.5–3.5：倾向调整后 Go（列出必须调整项）
- < 2.5：倾向 No-Go

## 决策前必答的四个问题

1. 最坏情况是什么？能不能承受？（最坏不是"做不成"，是"做不成还伤了主业"）
2. 哪个假设最重要？如果它是错的，这个想法还成立吗？
3. 验证它需要多少钱、多少时间？
4. 谁为这个决定负责？（决策者 = 人，不是 agent）

## 调整后 Go 的强制项

- 列明必须调整的维度与理由
- 列明重新评估的触发条件（什么情况回来重跑）
- 未满足条件前，不得进入 vibecoding-orchestration 需求锚定

## No-Go 的归档格式

归档到 `docs/00-requirements/raw/discarded/`：

- 想法一句话
- 否决维度与分数
- 否决原因（引用 G1 项或 G2 维度）
- 未来重启条件（什么情况值得重新看）
## 方向变动与回退规则

### 假设分层

- **核心假设**：一句话假设的三要素——为谁、解决什么问题、凭什么赚钱。被推翻 = 方向变了。
- **支持性假设**：市场规模、竞争格局、定价、渠道、合规细节等。被推翻 = 需要补证据或调整参数。

### 回退深度表

| 变动场景 | 回退到 | 重跑范围 | 例子 |
|---|---|---|---|
| 核心假设被推翻 | S0 | 重写一句话假设，版本 +1，旧版归档 | 调研发现真正付钱的是房东不是买家 |
| 支持性证据与结论冲突 | S2 | 只补受影响证据，重跑受影响维度 | 市场规模数据比预期小一个量级 |
| 触发 G1 否决项 | G1 | 重新判定 No-Go 或重定向 | 发现想法触碰平台规则红线 |
| 局部调整 | 不回退 | 当前环节内修订并记录 | 定价从抽佣改成会员费 |
| 调整后 Go 的调整项 | 对应环节 | 只重跑调整项相关部分 | G2 要求先验证获客成本 |

### 版本化规则

- 每次方向变动，把 01-idea-brief.md 升版本（v1 → v2），保留旧版文件（如 01-idea-brief-v1.md）。
- 变更记录格式：触发点 → 新证据/原因 → 回退到哪 → 重跑了什么 → 结论变化。
- 版本化的目的是可追溯增量，不是重新做一遍。

### 两个禁止

1. 禁止默认"从头重跑"：小调整也重跑全部环节是浪费。
2. 禁止无视新证据硬往下走：方向已变还按旧方向推进是自欺。

### 处理步骤

1. 记录：变动在哪个环节触发？什么新证据/新信息？
2. 判定：被推翻的是核心假设还是支持性证据？是否触发 G1 否决项？
3. 决定回退深度：按上表选最浅的必要环节。
4. 重跑：只重跑必要的环节和维度，其余沿用。
5. 升版本归档：更新 brief 版本、变更记录、决策简报。
