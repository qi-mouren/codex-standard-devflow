# 问题账（issues.md）

> 流程运行层问题的唯一登记处。由总控负责人统一登记与维护；子 agent 发现问题先上报总控，由总控登记。
> 只记**流程运行层**问题（环境/平台缺陷、评审遗留、流程偏差、延期缺陷、未决决策）；需求层的开放问题/废案记在需求锚点文档（docs/user/00-requirements/），不混入本账。
> 每条问题必须走到终态（fixed / deferred / wontfix），禁止长期滞留 open。

## 登记规则

- 登记时机：发现即登记（评审驳回项、G5 延期缺陷、环境缺陷、流程偏差、平台边界、用户决策挂起项）。
- 登记人：总控负责人（子 agent / 评审员上报 → 总控登记，避免多 agent 并发写同一文件）。
- 状态流转：`open`（登记）→ `triaged`（已分诊：定严重度+负责人）→ `fixed`（已修复，附证据链接）/ `deferred`（显式延期，附日期+理由）/ `wontfix`（不修，附理由）。
- 门禁联动：每个门禁通过前检查本账，存在未分诊 open 项或 Blocking 级未决项不得放行；G5 的延期缺陷必须登记为 deferred。

## 严重度定义

- **Blocking**：阻塞当前门禁/交付，必须先处理。
- **Major**：影响流程正确性/质量，本史诗内应处理。
- **Minor**：体验或整洁度问题，可排期。
- **Nit**：可改可不改，记录备查。
