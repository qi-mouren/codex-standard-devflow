# 史诗/模块/里程碑切分（splitting.md）

## 切分层级

```
产品 → 史诗（业务能力） → 模块（史诗内 3-8 个） → 里程碑（史诗按依赖汇合）
```

## 切分责任

| 切分 | 主责 | 辅助 | 审批 |
|---|---|---|---|
| 史诗 | 人类（业务能力边界） | 需求负责人 / 拆分官 agent 提候选 | 人类确认清单与顺序 |
| 模块 | 拆解负责人（agent） | 架构设计 作为输入 | 总控负责人 G3 机械校验 |
| 里程碑 | 人类（范围 + 日期是承诺） | 总控负责人推导依赖图 | 人类拍板 |

## 委托度配置

写在项目 AGENTS.md 中：

```
devflow:
  delegation: full | review
```

- `full`：切分全部委托 agent，前提是优先级/硬日期/资源约束/合规限制已写成输入文档。
- `review`（默认）：agent 起草全部切分，人类在唯一检查点 approve/veto。

全委托的两个前提（不满足不得 full）：
1. 信息补齐：业务优先级、硬性日期、资源约束、合规限制写成 docs/agent/epic-inputs.md（旧布局：docs/process/epic-inputs.md）。
2. 可验证标准：每个史诗有独立验收标准、依赖闭环、3-8 模块红线、薄片先行，违者可被脚本抓出。

## 史诗切分规则

1. 按业务能力切，不按团队或技术栈切。
2. 契约奠基史诗（定义用户/会话等平台级契约）必须最先跑。
3. 薄片先行：第一个史诗跑通最小可验证路径，验证架构后再横向铺开。
4. 每个史诗有独立交付验收标准。
5. 红线：需求锚定 蒸馏一个会话未收敛、PRD 超十几页、单史诗超 8 模块、单模块实现超 3 周 → 再切一刀。

## 模块切分规则（模块拆解）

1. 基于冻结的 HLD。
2. 按职责边界拆 3-8 个模块。
3. 模块间通过契约衔接，接口单一归属。
4. 每个模块输出：名称、职责、边界（做什么/不做什么）、依赖、验收入口。

## 里程碑定义规则

1. 里程碑 = 多个史诗按依赖累积成的可发布增量。
2. 依赖图由 总控负责人从契约注册表推导。
3. 范围和日期由人类拍板（对外交付承诺）。
4. 每个里程碑包含完整集成与回归，放大版 G5。

## 电商示例

| 史诗 | 定位 |
|---|---|
| EPIC-01 账户与认证 | 契约奠基，最先做 |
| EPIC-02 商品目录 | 完整跑一遍流程 |
| EPIC-03 购物车 | 独立跑流程 |
| EPIC-04 订单与支付 | 核心交易闭环 |
| EPIC-05 后台管理 | 依赖全部前置契约 |

里程碑：M1 = 01+02（薄片）；M2 = +03+04（交易闭环）；M3 = +05（完整可用）。
