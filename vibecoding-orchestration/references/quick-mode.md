# 快速模式（quick-mode.md）

> 降低小改动启动成本：不跑完整 G0-G5，保留"实现 ≠ 自评"底线。

## 触发条件（满足其一）

- 修 bug、加小接口、小重构：**不跨模块、不触碰契约、验收可直接判定、改动面小**（建议 <200 行）
- 不满足任一条 → 回 standard/enterprise 模式（走完整流程）

## 流程

1. **需求**：一句话 + 验收口径（可直接写在任务书里，不产出 PRD）
2. **任务书**：06-task 模板快速变体——任务/输入/输出/完成标准/**Scope Lock**/心跳（含 -TaskName）
3. **实现**：总控可直做（快速模式例外于"不代劳模块级工作"），或 spawn 执行 agent
4. **独立评审**：评审不可免（产出的节点不能当自己的裁判）——评审 agent 或用户
5. **G-quick PASS** → 提交 + STATE 变更记录一行

## 产物

- 只产出：任务书、代码变更/提交、评审记录
- 不产出：PRD / HLD / LLD / 契约变更（触碰契约即不属于 quick）
- STATE：变更记录一行 + Agent Registry 登记（如 spawn）

## 边界

- 触碰契约 / 跨模块 / 涉及架构决策 → 自动升级 standard 模式
- 快速模式不豁免心跳、watchdog、账本记录（小改动也是可追溯的）
